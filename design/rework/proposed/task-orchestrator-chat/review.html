  • The overview shows active worker previews across the top and decision cards beneath them, following the operator reference. Project and Running / Needs you filters work locally. Decision queue shows the pending task decisions without a global agent.
  • Each tile identifies its fixed orchestrator separately from the current worker. The task cost and global usage strip derive from the same plan 62 ledger. Model bars show shares of known processed tokens, without a fabricated quota or context figure.
  • The latest instruction intentionally changes the earlier mockup defaults for task ordering and previews: live previews are visible by default, and active tasks precede the decision cards in All tasks. This follows the supplied operator base while preserving plan 62 ownership and accounting.

  • The operator's embedded Doto accent, Segoe/Cascadia stacks and dark/light tokens are copied locally. The external review toolbar stays compact and separate. Optional suggested answers are hidden on narrow frames to leave room for question history and the sole composer.

Accounting and context

The 15 initial ledger rows sum to 400,000 processed tokens / $3.18 in fictional cost estimates. Task and role totals are derived subsets. Renewal adds one uniquely identified 3,000-token / $0.03 orchestration turn; repeating the event does not add it again. Unknown measurement adds an unavailable record beside the known subtotal.

Context displays selected sources, coverage and retained task memory separately from worker transcripts. The 8 KiB checkpoint, 32 KiB packet, 8 KiB/read, 16 KiB cumulative results and six-call figures are illustrative prototype bounds. Token estimates are separately supplied, not computed from bytes. Artifact inspection neither changes input coverage nor adds usage.

Runtime assumptions and boundaries

  • Route availability and adapter effort mappings are fictional snapshots from the plan. No installed CLI capability is asserted or probed.
  • The future service supplies task-bound actions, current revisions, validated evidence, accounting identities, ordered delivery and live gates. The mockup simulates those outcomes; it cannot prove their runtime enforcement.
  • Assignments are depicted as persisted before the first call; actual task files, checkpoint publication, credentials, provider metering and worker launches are not implemented.
  • Pause prevents new progression while an existing worker may continue. Stop ends sample execution, retains guidance and never schedules a retry. Unknown dispatch and delivery cannot replay automatically.
  • A context or checkpoint failure retains revision 7 and holds progression. Renewal changes the session while retaining route, effort, history and shared usage.
