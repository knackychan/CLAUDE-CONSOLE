Cells Drawer

A variant of Console Cells without the session rail. The open window is one plain list, like direction A: what needs you, what is working, what is done, each session a card you can read in words. Click a card and the session gets the whole window, with C's focus content in cells. A project picker in the header, drawn by the page and searchable, scopes the list and sets where a new task runs.

Design read

Reading this as: an always-on-top companion for one developer running several Claude Code sessions, read as a list of named tasks first and as instruments second, dial ENERGY 2 / RHYTHM 2 / MOTION 1.

  • Same tokens, type and cell motif as the locked Console Cells. Only the structure of the open window changes
  • ENERGY 2: one Doto figure per screen (today's spend on the list, the session's spend in its brief, smaller)
  • MOTION 1: the one blinking cell, on the "doing" line of each working card and on the live step of the session's process

Reading order on a card

  • State word with its glyph (ASKS YOU, BLOCKED, RUNNING, IDLE), task title, age. The title owns the line: nothing else on it grows
  • Second line, one size down, in fixed columns: project and route, cost, context as 30 small cells plus the figure. Costs and context line up down the list, so you compare by scanning one column
  • Third line by state: the question with an answer box, the denied command with Open in terminal, or "doing" with the live step
  • Done sessions fold to one quiet line each

Layout pass (2026-10-10)

  • Spacing scale 4 / 8 / 12 / 16 / 24: 6 px between cards of one group, 20 px above the next group label, so the groups read before the cards do
  • Session page reads top down: state and age, title, then project / source / route with New task here. The Doto figure comes after the head, not before the title. The steps list has a label like the other blocks
  • Composer: the task box takes the full width; "in CLAUDE CONSOLE" is a chip of the same family as the header scope, with the Enter = Prep hint on its right
  • 340 px: the window is a CSS container. Below 372 px the window buttons narrow to 28 px so "All projects" keeps its full name, the route leaves the card's second line (it stays on the session page), and the picker footer drops its sort note. Nothing scrolls sideways
  • Focus ring and text selection are ink, not orange, so orange keeps meaning "needs you" only. Scrollbars are thin and tinted from the tokens
  • States: the Empty and Error headings were mock labels dressed as UI and are gone. The empty list leads; a failed Prep card sits right above the composer that started it and offers Try again

Session page: brief and process

  • What folded: the 40 px spend figure, the context scale, the path, the agent lanes and the activity row were five stacked blocks that filled most of the 640 px and drew the eye before anything said what the session was doing. They are now one brief, 84 px at 400 px wide
  • The brief reads in one glance: the path as one row (✓ Prep, ▶ Run, Verify, Hand off), then one line of figures in fixed columns: spent (Doto 22 px, the only Doto figure on the page; an estimate shows its ~ in plain mono), $ / min, context as 30 cells plus the figure, time, steps. The columns stay put from session to session, so ‹ › compares in place
  • The brief is one button: click or Space opens the details in the same block (context with the hand-off marks, agent lanes with steps and cost, activity for the last 30 min), again folds them. Folded is the default, and the choice holds for the window, not per session: stepping with ‹ › keeps it. The app would keep it with the window form in window.json; the mock uses browser storage
  • Warnings do not fold away: from 150K the context label in the brief turns into "hand off soon" (orange), from 300K "hand off now" (red), in words next to the cells
  • The process takes the rest of the height: tabs Steps / Agents N / Timeline / Chat as in direction A, Steps first. Folded at 400 x 640 its pane is about 300 px, 14 step rows, where the old page showed three. Opened, the process keeps at least 200 px and the page scrolls
  • Steps is the live feed, newest first: time with seconds, agent, step. The one blinking cell marks the live step; a question gets ?, a denial ■ and its step in red. Agents: each agent with its state in words, steps, cost and last step. Timeline: one cell per minute, click a minute (or ← →) for its steps. Chat: the last turns in words, oldest to newest, scrolled to the end
  • One blinking cell per screen: it moved from the live agent's lane to the live step, and the lanes mark the live agent with ▶ instead
  • Every count agrees: the steps figure, the agent lanes, the Timeline cells and the Steps feed come from one sample log

Picking a project

  • Likely causes of today's trouble, to confirm before building: the native <select> opens an OS popup that a frameless, always-on-top WebView2 window handles poorly; the list mixes runnable projects with "(off)" ones, and picking an off one silently disables the task box; the chosen project is not visible where you type
  • The picker is drawn by the page, not the OS: it opens under the header, inside the window, and never closes when a new snapshot arrives
  • Built for many projects: a find box with focus on open (type two letters), Up / Down / Enter / Esc, Ctrl+P from anywhere. Rows sort by needs you, then live, then last activity; "Runs allowed" and "Runs off" are separate groups. Each row says what is going on there and what it cost today
  • One choice, two effects: a project scopes the list and becomes the target of a new task. All projects shows everything and keeps the last target
  • The target is always named under the task box ("in CLAUDE CONSOLE ▾") and opens the same picker. Opening a session sets it too, and the session page has "New task here"
  • The "need you" chip counts every project; clicking it clears the scope, so a filter never hides a question
  • Picking a project with runs off says why in words and offers "Allow runs" on the spot, instead of a greyed box

Kept and dropped

  • From A: list grouped by state, answer in place on the card, fixed columns, the drawer title bar, and on the session page the brief (head, path as one row, one row of figures) and the Steps / Agents / Timeline / Chat tabs
  • From C: the session page content (spend with burn rate, context against the hand-off marks, path, agents, activity, steps) and the levers bar. The instruments now sit folded under the brief, unchanged in meaning
  • Dropped: the rail, the rail-only strip, the session by minute heatmap (each card now carries its own state and cost; the session page keeps its activity row). On the session page: the 40 px Doto figure, the "doing" line under it (the Steps tab says it), and the Last steps block (now the Steps tab)

What it would touch

web/app.js (list renderer instead of renderRail, session page with prev and next, header picker instead of the c-project select), web/style.css, web/index.html. The service and state.py stay as they are for the list and the brief: every figure there is already in the snapshot, and the Steps and Timeline tabs read the step log with its timestamps. One new read: the last chat turns of a VS Code or terminal chat, from the transcript the service already reads for the estimate. If chosen, BRAINSTORM 7.5 and the locked file change with it.

Trade-offs

  • Two sessions are no longer visible side by side with the open one; ‹ › and the pill cover that
  • Past about 8 live sessions the list scrolls; Needs you stays first, so the important part never scrolls away
  • The scope is one more state to keep in mind; the header always names it, and the spend strip stays global
  • The hand-off scale and the agent lanes are one click away. The brief keeps the context cells and says "hand off soon / now" in words, so the warning never folds with them
  • Opened while a question is showing, the process drops to its 200 px floor and the page scrolls; that is why folded is the default
  • At 340 px the brief keeps its five columns by giving way: context goes back to the card's 15 x 2 cells and time drops its seconds. Timeline minutes are about 9 px wide there; ← → moves between them
  • Chat for VS Code and terminal chats needs the last turns read from the transcript (today Chat is for window runs only); it shows words only, tool output stays in Steps
