Why this shape

A companion window competes with VS Code for screen space all day. Most of the time the right amount of UI is three numbers: how many sessions need you, how many run, what today cost. The pill shows exactly that and earns more space only when it has something to say.

Window

Frame
Borderless (pywebview frameless=True), own title bar as the drag region, 10 px corners
Sizes
Pill 380 x 44, peek 380 x auto, drawer 400 x 640 (min 360 x 420)
Place
Snaps to the right edge of the screen it was on; position and fold state remembered in config.json
Controls
Always on top, fold, minimize, close. Double-click the title bar folds. Closing never stops a run, and the tooltip says so

Reading order on every card

  1. State, as a word chip ("Asks you", "Blocked", "Running"), with the glyph kept from today
  2. Task title, one line
  3. Age, right aligned
  4. Second line in fixed columns: where and route, cost, context. Numbers line up down the list, so you compare by scanning one column

Human-proof rules

  • Words before symbols. "STOP" becomes "Asks you", "Stall?" becomes "No activity 10 min"
  • Colour is never alone: chip word + glyph + tone. Amber means "you", red means "blocked or too big", everything else is quiet
  • Answers and fixes live on the card itself: answer box on a question, Open in terminal on a denial
  • Risky buttons confirm in place; every button shows "Sending…" until the service confirms
  • Context reads as "182K" with a tick at the hand-off mark, not an unlabeled bar
  • 12 px minimum text, 34 x 36 title-bar targets, Esc always goes back, Ctrl + / Ctrl - zoom

Cost and progress, honestly

  • $0.41 = exact, from a window run's result line. ~$1.92 = estimate for VS Code and terminal chats, from transcript token usage and a price table in config.json. New data: the hook would add usage per Stop
  • Progress is the playbook path (Prep, Run, Verify, Hand off) plus step and agent counts. No fake percent bar: the console cannot know how close a task is to done
  • Footer: today's spend, estimated share, model mix (phase 4 strip)

What it would touch

__main__.py (frameless, js_api for fold, pin and minimize), style.css (new tokens), app.js (card renderer, peek, fold state), state.py (estimated cost, today totals). No new dependency.

Trade-offs

  • Folded, you see counts, not names. Good for focus, weaker for "which one is still running?"
  • Programmatic resize between pill and drawer must be checked on Windows with a frameless pywebview window; fallback is a fixed small window instead of a true pill
  • Prep stays a full-height sheet over the drawer (not shown)
