Ring = context (fills toward the 300K hand-off mark, turns amber at 150K, red at 300K). Centre glyph = state. Badge = needs you. Hover a ring for the task title.

Why this shape

The other two directions treat sessions as a list. When one task matters (a long run you want to watch, a routing you doubt), you want one task big and the rest reduced to a glance. The rail keeps every session visible at 58 px without words; the pane gives the selected one the full height, so progress, spend and context are readable at a distance.

Window

Frame
Borderless, 12 px corners; drag from the rail grip or the pane's top bar
Sizes
Rail only 64 x 640, full 400 x 640, wider pane up to 560 for the Timeline
Fold
Rail-only strip docks to the screen edge, like a second taskbar; clicking a ring opens the pane on that task
Select
Auto-follows the session that just started asking, unless you picked one in the last 2 minutes (no focus stealing)

Following progress and cost

  • Doing now line in large mono, with which agent is doing it
  • Spend with burn rate ($ per minute over the last 5 min) and steps per minute: a dropping rate shows a stall before the Stall? rule
  • Context bar labelled with both marks ("150K soon", "300K hand off"), not a bare colour
  • Lanes per agent with cost at the end of each lane, promoted from the Timeline tab
  • Overview: all sessions as lanes over 60 min, today's exact and estimated spend, current burn
  • New data: estimated cost per session and per agent from transcript usage; per-minute buckets for the rates

Human-proof rules

  • Rings are never the only signal: glyph inside, badge outside, tooltip with the full state and title, and the same state in words in the pane
  • Project labels under each ring (short names from config, editable), so two rings are never told apart by colour
  • Asks-you view says exactly where the answer goes ("runs in a window copy; the VS Code chat stays as it is")
  • Stop confirms in place; close says runs continue; keyboard: Up / Down moves along the rail, Enter opens, Esc returns to Overview

What it would touch

__main__.py (frameless, resize between rail and full through js_api), style.css, app.js (rail, focus pane, overview lanes reusing timelineHtml), state.py (rates, estimated cost, per-agent cost). The detail view and Timeline tab become the main view instead of a second page.

Trade-offs

  • Rings carry a lot of meaning; needs a week to learn, then the fastest to read
  • Past 9 sessions the rail scrolls; Done sessions leave the rail and live in Overview
  • Window width changes on fold, same pywebview frameless resize check as Direction A
