Design 1/4: architecture

Three small pieces. One event log is the single source the view reads, whether a task started in VS Code, a terminal, or the mini window.

Data flow
VS Code session terminal session run started by the window \ | / \ | / global hooks (~/.claude/settings.json, async, never block) SessionStart UserPromptSubmit PreToolUse SubagentStart/Stop PermissionDenied Stop PreCompact/PostCompact SessionEnd | v 1. cc-events tiny script, appends one JSON line per event | ~/.claude/console/events.jsonl (+ transcript tail on Stop | = context tokens) v 2. console service Python, 127.0.0.1 only, tails the log, builds sessions -> agents -> steps, pushes SSE also runs: Prep claude -p (haiku, low, Read/Grep/Glob, JSON out) Run claude -p (route model + effort, auto mode, --permission-prompts none, stream-json) Handoff claude -p "/session-handoff" --resume id Open in terminal claude --resume id (new terminal) | v 3. mini window pywebview, always on top, ~420 x 640 Prep card (review, Run / Run raw / Edit) Tree view (sessions, agents, gauge, red blocked events) Session detail: prompt, steps, tokens, verifier, Timeline tab

Checked against docs / this machine

  • Hook events incl. SubagentStart/Stop, PermissionDenied (auto mode); hooks can be async
  • Every hook gets session_id, cwd, transcript_path, permission_mode, effort, agent_type
  • -p: --model, --effort, --permission-mode auto, --permission-prompts none, --resume
  • -p expands /skill-name, so Handoff works headless
  • stream-json marks subagent messages with parent_tool_use_id (nesting tree)
  • Transcript lines carry usage: input + cache_read + cache_creation = context tokens
